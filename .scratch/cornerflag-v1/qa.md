# CornerFlag v1 — 설계 QA 기록

2026-10-19 설계 세션에서 오간 질문과 답. 12절부터는 같은 날 이어진 디자인 세션의 기록이다. 각 질문의 선택지 중 `(추천)`은 질문 당시 제시한 권장안이고, **답**은 최종 결정이다. 이 결정들을 정리한 명세는 [spec.md](spec.md), 화면·버튼·표시 내용은 [design.md](design.md), 검증 결과는 [verification.md](verification.md)에 있다.

## 0. 출발점 (사용자 초기 구상)

1. 정보는 최소한만 보여준다. 경기를 클릭하면 기본 브라우저로 구글 검색을 연다 (예: `Premier League Manchester City vs Arsenal`).
2. 데이터는 ESPN API를 쓴다.
3. 응원 팀은 첫 실행 때 고르고 설정에서 바꿀 수 있다. 그 팀 정보만 표시한다.
4. 스택은 미정.
5. GitHub Releases로 배포한다. 설치 파일(.msi)과 폴더 배포 중 미정.
6. 디자인은 미니멀하게.
7. 직전 경기 결과는 48시간 표시하고, 이후에는 다음 경기를 표시한다. 다음 경기까지 24시간 이내면 다음 경기를 우선한다.
8. 갱신 주기: 경기 없을 때 1시간, 진행 중일 때 10초, 킥오프 예정 시각 ±5분 동안 1분. 수동 새로고침 버튼도 둔다.

표시 우선순위는 **실시간 > 24시간 이내 다음 경기 > 48시간 이내 직전 결과 > 다음 경기**로 해석했고, 이의 없이 확정됐다.

## 9. 갱신 중지·오류 정책 (사용자 추가 질문)

사용자 질문: 위젯이 다른 창에 가려지면 10초 갱신을 멈추고, 다시 보일 때 즉시 1회 갱신한 뒤 10초 간격으로 돌아오는 방식이 가능한가? 4xx 오류(요청 과다 등)가 나면 어떻게 할지도 정하고 검증하자.

답변 요지:
- 가려짐 감지는 Rust 쪽에서 직접 계산해야 구현할 수 있다. 다만 아끼는 양이 작다(실측상 10초 갱신 1회가 수 KB). 대부분의 리소스는 WebView2 상주 메모리라서 갱신을 멈춰도 줄지 않는다. 반투명 오버레이 때문에 "가려짐"으로 잘못 판단하면 보이는 위젯의 스코어가 멈추는 위험도 있다.
- ESPN 오류 응답을 실측해서 오류 분류 정책을 제안했다 ([verification.md](verification.md) 1절).

## 11. 질문 없이 정한 기본값

설계 중 별도 질문 없이 기본값으로 정하고, 사용자에게 변경 가능하다고 알린 항목이다.

- 48시간은 킥오프 시각부터 계산한다.
- 다음 갱신 시각은 "1시간 뒤"와 "킥오프 5분 전" 중 이른 쪽이다.
- 하프타임·연장·승부차기 동안에도 10초 간격을 유지한다.
- 절전에서 깨어나거나 네트워크가 복구되면 바로 갱신한다.
- 수동 새로고침은 5초 쿨다운을 둔다.
- 앱은 하나만 실행된다(single-instance).
- 팀 색이 없으면 중립색을 쓴다. (색이 배경과 비슷할 때 중립색으로 바꾸려던 규칙은 36번 결정으로 폐기)
- ESPN이 정보를 주면 득점 줄에 PK는 `(P)`, 자책골은 `(OG)`를 붙인다.
- 승부차기는 `1–1 (4–3 PEN)`처럼 표기한다.
- 검색어 날짜는 킥오프의 UTC 날짜로 한다. 유럽 경기는 현지 날짜와 같고, 한국 날짜로 하면 하루 밀리기 때문이다.
- 라이선스는 MIT.

## 13. 목업 검토 후 결정

HTML 목업(`mockup.html`, 70번에서 삭제. git 기록과 Figma `Archive`의 `00 Baseline`에 남아 있음)에서 글꼴 6종(Segoe UI Variable, Inter, Barlow, Saira, Outfit, Manrope), 크기, 틴트, 불투명도를 비교한 뒤 정했다. 49–51번은 사용자가 직접 제안했다.

| # | 항목 | 답 |
|---|---|---|
| 45 | 글꼴 | **Outfit** |
| 46 | 틴트 강도·범위 | **강도 50%, 범위 100%** (이긴 쪽 가장자리에서 반대쪽 끝까지) |
| 47 | 카드 크기 | **기본 320×136px. 비율 고정, 설정에서 사용자가 조절** |
| 48 | 불투명도 | **설정에서 조절, 기본 70%** |
| 49 | 팀명 | **ESPN `shortDisplayName`** (예: `Man City`, `Spurs`) |
| 50 | 클릭 안내 | **마우스 오버 시 오른쪽 아래에 `More details ↗`** |
| 51 | 실시간 득점 줄 | **경기 줄과 득점 줄 사이에 구분선 하나** |

- 47번은 27번에서 고르지 않았던 "크기 배율"을 설정에 다시 넣은 것이다.
- 49번은 15번(`displayName`)을 바꾼 것이다. 5대 리그에서 가장 긴 `shortDisplayName`은 13자(`Real Sociedad`)라서 기본 크기에서 거의 잘리지 않는다. 구글 검색어에는 계속 `displayName`을 쓴다 ([spec.md](spec.md) 5.2절).
- 50번 사용자 메모: "클릭하면 추가 정보를 볼 수 있다"는 것을 바로 알 수 있게 한다. 별도 버튼이 아니라 안내 표시다.
- 51번 사용자 메모: 실시간 카드는 `(홈팀) (점수 – 점수) (원정팀)` / 구분선 / `(골 문구) (More details ↗)` 구조다.

## 14. 디자인 기본값 (질문 없이 정함)

- 로고는 ESPN `logos` 중 `dark` 변형을 쓰고, 없으면 `default`를 쓴다. EPL 20팀 중 Coventry City만 `dark`가 없다.
- 승부차기로 끝난 경기는 승부차기 승자의 색으로 칠한다.
- 모서리 반경 8px, 1px 흐린 테두리 (Win11 창과 같음).
- 아이콘(↻, ↗, ⚠)은 인라인 SVG.
- `Postponed`는 호박색 pill 배지.
- 바닥 줄은 모든 상태에서 자리를 차지해서, 상태가 바뀌어도 경기 줄 위치가 그대로 있다.
- 경기 없음 상태에서는 클릭해도 아무 일도 없고, 호버 시 `More details`도 나오지 않는다.
- 설정은 바꾸는 즉시 반영하고 저장 버튼을 두지 않는다.
- 첫 실행 창을 팀을 고르지 않고 닫으면 앱을 종료한다.

질문 없이 정한 기본값:
- 득점 플래시와 점수 굴림은 갱신에서 점수 변화를 처음 확인했을 때 한 번만 재생한다. 앱을 다시 켜서 캐시로 그린 경우에는 재생하지 않는다.
- `Refresh now`는 쿨다운·요청 제한 동안 흐리게 표시하고 남은 초를 보여준다.
- Settings 창: 선택된 팀은 바탕 + 테두리 + 키트 줄로 표시. 토글·슬라이더·두 칸 선택은 각진 모양. 맨 아래 `Changes apply immediately.`
- About 창: 앱 이름(글자), 버전, 업데이트 상태, 응원 팀, 마지막 갱신 시각, 데이터 출처, 라이선스, GitHub 링크.
- 첫 실행 화면은 Settings 창의 팀 영역에 `Start with Windows`와 `Start` 버튼을 더한 것으로 둔다. Figma에는 아직 그리지 않았다.
